# PROPOSAL-0026 Torch row-context diagnosis

## Root cause verified before the change

Source artifact: `/Volumes/DATA2/TEST_sentinel-1/faninsar-experiments/PROPOSAL-0026/diagnosis-current-vs-prior/root-confirm.json`.

The current public CUDA matrix times the synchronized `execute_geometry` call,
including input validation, device materialization, dispatch, output
materialization, and synchronization.  The earlier direct-array benchmark
used GPU-resident inputs and timed the solver only.  They are therefore not
cross-campaign speedup measurements.  In the current matrix, Compile uses a
fixed `max_iter=4` graph while Eager exits from the masked loop early; the
observed ratios are Compile/Eager `2.063x` for `geo2rdr` and `2.457x` for
`rdr2geo`, with Native/Eager `1.017x` and `1.005x`, respectively.  The older
direct-array `rdr2geo` signal was Compile `34.700 ms`, Eager `225.290 ms`, and
Native `76.707 ms`, which explains the apparently lost advantage.

## Change and verification

For a two-dimensional input whose azimuth values are identical across each
row, `torch_kernels._rdr2geo_geometry_state` now evaluates orbit/local-frame
state at shape `(rows, 1)` and expands it to the point grid.  One-dimensional
inputs and irregular two-dimensional rows use the original point-wise path.
Compiled capture uses device-side `torch.cond`; eager execution selects the
same branch without compiling the higher-order operator.  No `.cpu()`,
`.numpy()`, or host branch is used while an outer `torch.compile` graph is
being captured.
